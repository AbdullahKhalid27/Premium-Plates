# F1-02 · Make releases identifiable and recoverable
Status: implemented and locally verified; GitHub CI and PR review pending.
Blocked by: F1-01 for integrated verification.
## User outcome
The operator can identify version 0.2.0, inspect CI results and restore a previous static release.
## Work
Version footer and release page, PR build workflow, explicit deployment commit input and release operations runbook. Document the single-main branching and review convention.
## Acceptance
Build produces release route. PR workflow builds the app. Manual deployment accepts an immutable SHA. Recovery instructions cover smoke checks, failure handling and future server/data rollback boundaries.
## Validation
Build/export, inspect workflow, rehearse a local clean build from the baseline when dependencies are available. Do not claim a production rollback rehearsal until a deployment is performed.
